Things to try

  1. Send coins from one node to another and follow the orange dot as the transaction spreads.
  2. Turn on mining for more nodes and watch who wins each block.
  3. Take a node offline, let it keep mining alone, then bring it back. Its short fork gets replaced by the longer chain.
  4. Cut two connections to split the network in half. Both halves keep mining until you reconnect them.
  5. Press “Try a double spend” and see which of the two payments ends up in a block.
  6. Open a block and change its nonce. The hash changes and the proof of work breaks.

How it works

Keys and addresses

Every node holds a real ECDSA key pair (P-256). Its address is the SHA-256 hash of its public key, shortened. Only the private key can sign coins away from that address.

Transactions

Coins are unspent outputs (UTXOs) of earlier transactions. A payment uses some of them as inputs, signs each one and creates new outputs: one for the receiver and one for the change. Whatever is left over is the fee.

Mempool

Each node checks the signatures and that the coins are still unspent, then keeps the transaction in its mempool and passes it on to its peers. A second payment that spends the same coin is rejected.

Proof of work

Miners collect transactions into a block and try one nonce after another until the block's SHA-256 hash starts with enough zeros. Each extra zero makes this about 16 times harder. The winner gets 50 SIM plus the fees.

The chain

Each block contains the hash of the block before it. Changing anything in an old block changes its hash, which breaks every block after it. That makes history expensive to rewrite.

Consensus

Nodes follow the chain with the most total work. When two miners find a block at the same time, the network forks briefly. The next block settles it, and the losing block's transactions return to the mempool.
